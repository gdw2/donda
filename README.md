# Donda Alexa Skill

Alexa skill for looking up the school lunch menu. Invocation: "ding dong".

## Architecture
- **Alexa Skill** → **Cloudflare Tunnel** → **Express server** → **LinqConnect school lunch API**

## Setup

### 1. Install dependencies
```bash
npm install
```

### 2. Deploy skill to Alexa
```bash
npx --yes ask-cli@2.30.7 deploy
```

### 3. Start server and tunnel

Terminal 1 - Start the server:
```bash
npm start
```

Terminal 2 - Create Cloudflare tunnel:
```bash
cloudflared tunnel --url http://localhost:8080
```

Update the endpoint URI in `skill-package/skill.json` to match your tunnel URL, then `ask deploy` again.

## Usage
The Alexa interaction model is intentionally domain-agnostic — it only exposes a single
`ChatIntent` with an `AMAZON.SearchQuery` slot plus generic carrier samples. Invoke it with
a carrier verb:

- "Alexa, ask ding dong to tell me what is for lunch today"
- "Alexa, ask ding dong to tell me what is for school lunch tomorrow"
- "Alexa, ask ding dong about lunch on Friday"

Or open a multi-turn session (recommended) and speak freely afterwards:

- "Alexa, open ding dong" → "what's for lunch today" → "what about tomorrow?"

Responses are generated by formatting the LinqConnect menu data directly (no external AI service).

## How Requests Are Routed
The server runs the free-form `userText` through an `IntentMatcher` (see below) that
classifies it into `get_lunch_today`, `get_lunch_tomorrow`, `help`, `exit`, or unrecognized.

- Matched lunch intent → fetches that day's menu and reads it aloud.
- Specific weekday mentions in the text (e.g. "on Friday") always win over the matcher.
- Bare day tokens / empty text (common for free-form in-session speech) default to today.
- `help` / `exit` / unrecognized utterances get friendly canned responses.
- ChatIntent and help responses keep the session open so follow-ups need no carrier;
  exit / stop / cancel end the session.

Set `DISABLE_INTENT_MATCHER=1` to skip sentence-embedding routing and fall back to
keyword date parsing only.

## Intent Matching
The `intent/` module routes free-form utterances to intents using sentence embeddings
(runs `all-MiniLM-L6-v2` locally via transformers.js — no external API).

- `intent/intents.js` — intent definitions (`key` + sample utterances)
- `intent/intent-matcher.js` — reusable `IntentMatcher` class:
  - reference samples are embedded once at startup and cached to disk
    (`intent/.cache/`), so only the incoming utterance is embedded at request time
  - matches by cosine similarity; returns best intent + confidence score
  - configurable `threshold` (default 0.75) below which inputs are treated as unrecognized
  - CPU threads capped (`numThreads`, default 2) for concurrent-hit safety
- `intent/example.js` — demo runner

```bash
npm run intent-demo     # run the matching demo
node intent/example.js  # or directly
```

Example intent schema:
```js
const INTENT_DEFINITIONS = [
  {
    key: 'get_lunch_today',
    samples: [
      "what's for lunch today",
      "what's for lunch",
      "what's on the school lunch menu"
    ]
  },
  {
    key: 'get_lunch_tomorrow',
    samples: [
      "what's for school lunch tomorrow",
      "what's tomorrow's lunch menu",
      "what are we eating tomorrow"
    ]
  }
];
```
